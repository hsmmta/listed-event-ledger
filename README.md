# 上市公司事件追踪与核验助手

研究人员可以批量导入中文合同材料，查看程序抽取的公司、项目、动作、金额和引句，并按信息披露时间回看。当前使用本地规则与 SQLite。时间线在同一公司和交易对手内按可见的合同编号、原文明确说明的项目别名及项目名组织材料，有歧义的归属单列待复核。

**第一阶段定版 V1.5。** 对照打开 [15:59 的雨水回用事项](out/V1-雨水回用-披露前.html) 和 [16:00 的同一事项](out/V1-雨水回用-披露时.html)，可以看到新公告何时进入时间线。点击 A3 下的“定位原文”核查 260 万元的出处。[第一阶段验收记录](eval/reports/V1.5-首版验收.md) 保存了浏览器实测、直接总结原答和一次错引修复。

**第二阶段 V2.1。** 在“使用虚构样例”中选择“导入多合同归并示例”，或打开[离线归并与复核页面](out/V2.1-合同归并与复核.html)。在复核区找到 B05，点候选合同 HT-02 查看 B08 的 320 万元，再点证据出处核对原句。运行 `python -m eval.score_links` 可复测八份固定开发材料。[V2.0 基线](eval/reports/V2.0-多合同归并基线.md) · [V2.1 复测](eval/reports/V2.1-合同归并复测.md)

## 本地使用

Windows 安装 Python 后，双击根目录的 **启动事项追踪.cmd**。页面使用本机数据库。在空库中展开“使用虚构样例”并导入，即可查看示例。展开“录入一份材料”可以直接输入新内容。选择披露时间后点击“查看该时点”，页面按当时可用的材料重建。关闭启动窗口即退出，已导入的数据会保留。同样可以在终端运行 `python -m app.local`。

每次查询先按披露时间选取材料，再计算该截面的合同归属。编号清楚的合同使用由公司、对手及合同编号确定的稳定事项标识；只有项目全名的材料沿用本库基础编号。后续披露可以澄清早先材料的归属，早期截面仍只使用当时的依据。页面和 JSON 共用同一套结果，JSON 的“合同编号”表示归属合同，“归并依据”和“归并证据”说明编号来自本材料还是其他已披露材料。旧库可直接打开。复核区支持查看候选合同和证据，人工改判留痕按后续阶段安排。

## 直接看成果

下载后双击 [八份虚构材料的证据预览](out/11月26日-事件证据预览.html)，点击某条说法下的“定位原文”，即可在全文中高亮该句并查看上下文。页面的位置从第 1 字起算，JSON 中的起点和终点可以直接用于 Python 切片。[历史截面](out/11月4日-历史截面.html) 只展示 11 月 4 日 15 时之前已披露的材料。两个页面都是可离线打开的导出结果。

## 自己运行

在项目根目录打开终端。需要 Python 3.10 或以上，仅使用标准库。依次执行以下命令。

```powershell
python -m src.event_tracker import data/examples/D1-D5.json
python -m src.event_tracker import data/examples/D6-D8.json
python -m src.event_tracker show --html out/我的预览.html --json data/processed/抽取结果.json
python -m src.event_tracker show --until "2026-11-04 15:00" --html out/我的历史截面.html
python eval/run_eval.py
```

首次导入分别新增 5 和 3 份材料，再运行计为重复。打开 out/我的预览.html 查看新结果。自己的材料按示例填写“编号、发布时间、来源、正文”。同编号内容发生变化会提示冲突并保留原文，单项失败可修正后重新导入。

## 文件放在哪里

- 项目工作文档仅保存在本地 `docs/` 或 `doc/`。
- `data/raw/` 本地原始材料，按企业样例、公告、新闻等存放，按只读约定使用。`data/examples/` 是可随仓库分发的虚构输入，不含参考答案。
- `data/interim/` 是可由输入重建的 SQLite 工作库。`data/processed/` 是结构化抽取结果。`data/groundtruth/` 放逐条人工标注，手工维护。
- `src/ingest/` 导入、去重，`src/extract/` 合同抽取，`src/common/` 存储和时间处理。`src/link/` 构建事项候选，`src/verify/` 预留给核验。`app/` 生成预览。
- `eval/cases/` 只放题目，`eval/expected/` 放按题号关联的答案。`eval/reports/` 保存每次运行报告。当前自动检查为开发回归，独立评测尚待开展。
- `out/` 保存页面和展示产物。`archive/` 保存历史资料。

Git 跟踪公开虚构输入、代码、虚构样例快照与回归记录。原始材料、人工标注、数据库、一般导出、本地聊天归档与环境密钥默认忽略。

目录调整原则、中文提交格式和阶段版本号见 [项目协作约定](AGENTS.md)。
